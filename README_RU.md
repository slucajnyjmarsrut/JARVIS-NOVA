# JARVIS NOVA Python Agent RC3 — сборка одного Windows EXE

## Что это
Исходный код нового агента на Python с конфигурацией PyInstaller.
**Это НЕ собранный EXE.** Windows-сборка выполняется через GitHub Actions или на Windows.
Нельзя собирать Windows-версию PyInstaller непосредственно на Linux.

В приложении (программная реализация; не означает испытания на Windows):
- Минималистичное одно окно Tkinter без отдельной PowerShell-консоли.
- Постоянное офлайн-распознавание Vosk, активация «Джарвис».
- Автоматический резервный Whisper (base) для сегментов, где Vosk не обнаружил обращение «Джарвис», включая случай, когда Vosk распознал другие слова. Есть ограничение частоты повторных запусков.
- Русский Silero TTS v5 (при успешном загрузочном тесте); запасной системный Windows TTS.
- Запуск Windows-программ из ярлыков меню Пуск; базовое управление окнами и масштабом.
- Курсор, клавиатура и ввод текста **с разрешениями и подтверждением**.
- Вопрос «что на экране?» — изображение только в оперативной памяти; запрос только в ЛОКАЛЬНУЮ Ollama с vision-моделью, если она отдельно установлена.
- Необязательное планирование действий: Ollama, OpenAI API, Claude API.
- Без выполнения произвольных команд PowerShell/shell, без автоудаления файлов и без незаметных действий.
- F9 — ручная голосовая активация, когда JARVIS в фокусе (основной путь — голосовое обращение).

## Комплектация одного EXE
Сценарий `build_models.py` на **машине сборки** загружает `base.pt`
(Whisper base) и `v5_ru.pt` (Silero v5_ru). Файлы включаются в EXE
при сборке `jarvis_agent.spec`, вместе с Vosk, PyTorch и Python.
На компьютере пользователя для этих трёх движков **не нужно скачивать веса**.

**Ограничение:** PyInstaller --onefile при старте распаковывает ресурсы
во временную папку. Размер может превышать 1 ГБ, первый запуск будет
заметно медленнее. Это нормально и не означает запись скриншотов.
Работа микрофона, PyTorch/Silero и Windows API на реальном ПК ещё НЕ проверена.

**Ограничение AI-зрения:** модели для понимания любых изображений
внутри этого EXE нет; при подключённой локальной Ollama с vision-моделью
оно будет работать без облачной отправки скриншотов.
Полностью универсального автономного управления любыми программами нет.

## Собрать на GitHub Actions (не нужен Android SDK)
1. Распакуйте ZIP в репозиторий GitHub, сохранив `.github/workflows/build-exe.yml`.
2. Откройте `Actions` → `Build JARVIS Python Agent EXE` → `Run workflow`.
3. Windows-сборщик заранее загрузит модели, проверит SHA-256 Whisper,
   протестирует синтез Silero, загрузку Whisper и Vosk, выполнит unit-тесты.
4. Дождитесь успешного выполнения, скачайте `JARVIS-NOVA-PYAGENT-WINDOWS`
   из Artifacts. Внутри EXE и SHA256SUMS.txt.
5. Для проверки: запустите EXE на Windows 10/11 x64, дайте доступ к микрофону,
   скажите «Джарвис, открой Chrome». Для мыши сначала выдайте разрешение в меню.

**Сборка не проверена на GitHub Actions из этой сессии.**
Возможно, будут необходимы дополнительные hooks/PyInstaller-зависимости для
конкретной версии PyTorch и Windows. При проблеме пришлите журнал Actions.

## Собрать на Windows
- Установите Python 3.11 x64 на **машине разработчика**, не у конечного пользователя.
- `python -m pip install torch --index-url https://download.pytorch.org/whl/cpu`
- `python -m pip install -r requirements-windows.txt`
- `python build_models.py`
- `python -m unittest discover -s tests -v`
- `python verify_models.py` (проверка реальной загрузки и инференса)
- `python -m PyInstaller --noconfirm --clean jarvis_agent.spec`
- Получившийся `dist/JARVIS-NOVA-PYAGENT.exe` предназначен для запуска без Python.

## Права и безопасность
Разрешения на управление и зрение сбрасываются после завершения сеанса.
Удаление файлов, команды shell, покупки, питание ПК не предусмотрены.
Все AI-предложенные шаги требуют ручного подтверждения.
Кадры изображения только в памяти; они не сохраняются в файл и не
отправляются в облачные AI API. Не включайте доступ к экрану при показе
паролей и другой секретной информации даже локальной модели.

Облачное планирование (не обязательно) требует личного API-ключа в
`OPENAI_API_KEY` или `ANTHROPIC_API_KEY`. Ключи НЕ входят в EXE.
Локальное планирование использует Ollama по `127.0.0.1`.
Если внешнего AI нет, работают встроенные локальные команды.

## Реальность предоставленных архивов
- `whisper-20250625.zip`: код Whisper без весов. В Windows-сборке
  используется соответствующий пакет `openai-whisper==20250625`;
  модель загружается на машине сборки.
- `SileroTTS_Ru_Setup_1.0.2.exe`: установщик Inno Setup, но его состав
  модели здесь не подтверждён. Не запускаем и не перепаковываем чужой
  EXE, используем официальную модель Silero v5.
- Модель Vosk взята из доступных исходников JARVIS NOVA 3.6 (её LICENSE
  — GPLv3), а не из установщика Silero.

## Ожидаемые ограничения
Шёпот через Bluetooth HFP по-прежнему может распознаваться плохо.
Наличие Whisper повышает число способов распознать фразу, но
точность на конкретных Soundcore Space One не измерена.
PyInstaller сам по себе не создаёт «умный AI»: он только упаковывает
код и модели, и не заменяет разрешений Windows и совместимое железо.

## Исправления в сборочном проекте RC1

- Whisper повторно анализирует фразу, когда Vosk не обнаружил ключевое слово.
- Добавлена пауза между попытками Whisper, чтобы не перегружать CPU.
- Распознавание при озвучивании временно блокируется для уменьшения эха.
- Выполнение действий и сетевые запросы зрения вынесены из UI-потока.
- Исправлен pip-cache путь в GitHub Actions.
- В `verify_models.py` добавлена проверка совместимости моделей **на Windows-сборщике**.
- Выполняются 24 автоматических теста без настоящего микрофона.

Никакие из этих результатов не доказывают, что микрофон, Silero и Windows GUI
отработали корректно **на ПК пользователя**. Настоящего собранного EXE здесь нет.

## Изменения RC3
- Новый `bootstrap.py`: `multiprocessing.freeze_support()` вызывается
  **до** запуска интерфейса и голосовых библиотек. Это предотвращает
  зацикливание запуска дочерних PyInstaller-процессов.
- Vosk начинает запускаться до тяжёлой загрузки PyTorch/Silero.
- `JARVIS-NOVA-PYAGENT.exe --self-test` проверяет модель Vosk, Silero,
  Whisper и импорт библиотек внутри готового EXE, не используя микрофон.
- GitHub Actions сначала тестирует модели из исходного проекта, затем
  собирает EXE и проверяет уже **сам готовый EXE**.
- 31 модульный тест пройден в доступной Linux-среде.

### Не путать с готовым Windows EXE
Ни один Windows EXE PyInstaller в этом архиве не лежит.
GitHub Actions нужно запускать **в Windows-раннере**. Пока его реальный
успешный результат здесь не получен. В случае ошибок Windows-раннера
настройка сборки может потребовать дополнительного исправления.
Загружаемые модели Silero и Whisper доступны конечному пользователю
только *после* успешного завершения этой сборки.
