# JARVIS NOVA — безопасное саморазвитие и обновления

**Статус: защита усилена, но полная безопасность не гарантируется.**
Этот документ описывает действующие запреты и необходимые шаги
перед настоящим самостоятельным обновлением программы.

## 1. Самоисправление — только исходники и только jarvis

- Пользователь описывает проблему или размечает скриншот.
- Локальная Qwen (либо FreeLLM с отдельным предупреждением) предлагает
  исправление одного разрешённого Python-файла интерфейса.
- Полный diff и новый файл показываются до записи.
- Предложенный код НЕ запускается во время предпросмотра: проверяется AST.
- Запрещены новые импорты в автоматических предложениях, выявленные новые
  опасные вызовы, изменения функций с чувствительными операциями.
  Это **не песочница и не математическое доказательство безопасности**.
- До записи требуется явное подтверждение пользователя.
- Разрешён только исходный клон JARVIS-NOVA с официальным origin и
  активной Git-веткой jarvis. Ветка main не изменяется.
- Предложенные и исходные SHA256 проверяются повторно перед записью.
- Создаются резервные копии; отмена запрещается, если файл изменился позже.
- Ни git push, ни публикация релиза, ни установка EXE не происходят
  из команды «исправь себя».

## 2. Конфиденциальность локального ИИ

- Локальный текстовый чат обращается к 127.0.0.1, без HTTP-прокси.
- HTTP-переадресации запрещены, в том числе на другой адрес loopback.
- URL с учётными данными отклоняются, в том числе с пустым именем пользователя.
- Анализ загруженного скриншота использует локальную Qwen. Оригинал не меняется.
- Для передачи файлов исходников через FreeLLM требуется отдельное разрешение.
- Модель и скриншот считаются недоверенными данными, а не источником полномочий.

## 3. Обновление: SHA256 + цифровая подпись издателя

SHA256, возвращённый GitHub Releases, проверяет целостность скачанных байт,
но **не подтверждает, что это подписанный JARVIS NOVA**. Поэтому новая
защита требует два независимых условия:

1. Совпадение размера и SHA256 официального стабильного релиза.
2. Действительная Windows Authenticode-подпись установщика, и
   SHA256 DER-сертификата подписанта равен заранее закреплённому значению
   `PINNED_PUBLISHER_CERT_SHA256` в `publisher_trust.py`.

**Сейчас сертификат издателя не закреплён. Автоматическое скачивание/
установка обновления отключены намеренно.** Ни пользовательский чат,
ни API GitHub, ни переменные окружения не могут назначить доверенный
сертификат. Подпись проверяется до закрытия JARVIS, и снова перед запуском
установщика отдельным процессом. Дополнительно проверяется подпись
JarvisNovaUpdater.exe — до копирования и после копирования в каталог
обновлений. Системная программа проверки запускается из Windows
System32, путь к которому получается через kernel32, а не из
переменной окружения SystemRoot.

Как подготовить настоящие безопасные релизы:

1. Владелец проекта получает законный сертификат подписи кода для
   JARVIS NOVA; приватный ключ НЕ хранится в репозитории.
2. Вне приложения проверяется принадлежность сертификата издателю,
   корректность цепочки и возможность подписания Windows EXE.
3. Вычисляется SHA256 **DER-байтов сертификата**, проверяется независимо,
   затем закрепляется в исходниках ветки jarvis через код-ревью.
4. Только доверенный CI-процесс подписывает установщик; проверяется
   Authenticode Valid, отсутствие незапланированных бинарников,
   тесты Windows и SHA256 релиза.
5. Лишь после проверки нового установщика на чистой Windows и
   сохранности пользовательских данных он может стать стабильным
   GitHub Release.

**Важно:** у проекта пока нет опубликованных стабильных Releases;
не следует считать DEV-артефакты готовыми безопасными обновлениями.

## 4. Отсутствие скрытых перезапусков

- Автоматическая проверка версий может оставаться включённой, когда
  появится подтверждённый издатель.
- Автоматический перезапуск по умолчанию **выключен**.
- Старые настройки формата v1 больше не означают явное согласие на
  перезапуск; для него потребуется новое сохранение пользовательского выбора.
- Пункт меню обновлений показывает причину запрета и отключает кнопки
  проверки/установки, если издатель пока не подтверждён.
- Незавершённые сообщения, активный монтаж и несохранённая работа
  блокируют автоматическую установку.

## 5. Проверки, которые не заменяют реальные испытания

GitHub Actions проверяет Windows 2022/2025 и Ubuntu: запрет опасных
изменений, безопасный diff, отказ в обновлении без подписи, локальный
HTTP без переадресаций, восстановление резервных копий и отказ при
чужих правках. Тесты с искусственными EXE **не доказывают** безопасность
настоящего установщика; нужны реальная подпись и физическая Windows-машина.

## 6. Остаточные риски и следующие этапы

- Автогенерируемый Python-код может быть ошибочным несмотря на AST-анализ.
- Приложение и его исходный клон работают с правами пользователя; они
  не изолированы от других процессов с теми же правами.
- Настоящий откат **уже частично установленного** Inno Setup не
  гарантируется одним перезапуском прежнего EXE; нужен отдельный
  проверенный механизм образов/снапшотов установленной версии.
- Потребуются независимое код-ревью, изолированная сборка, подписание
  Windows-приложения, проверки реальной Qwen, Studio и Roblox.
- До выполнения этих условий самостоятельные релизы и самоустановка
  сгенерированного кода остаются **отключены**.
