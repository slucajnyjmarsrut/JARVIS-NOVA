# NOVA SELF-DEVELOPMENT — защищённый первый этап

В текстовом JARVIS NOVA введи «исправь себя». Можно сначала отправить
скриншот, нарисовать красные отметки и дождаться результата локального
Vision-анализа. Следующая команда «исправь себя» использует это описание.

## Как пользоваться

1. Установи локальную Qwen с подтверждением через ⚙ либо отдельно
   разреши использование FreeLLM (исходники будут отправлены провайдеру).
2. В меню ⚙ выбери «Самоисправление · только jarvis» или напиши эту
   команду в чате.
3. Выбери исходный клон проекта JARVIS-NOVA из GitHub. Он должен иметь
   официальный origin slucajnyjmarsrut/JARVIS-NOVA и ветку jarvis.
   Установленная программа не является исходным клоном. Клон можно
   получить в GitHub Desktop и там переключиться на jarvis.
4. Выбери один из разрешённых файлов интерфейса, опиши проблему,
   нажми «Подготовить исправление».
5. JARVIS сгенерирует предложенную новую версию одного файла и проверит
   синтаксис Python (AST) без запуска предложенного кода.
6. Внимательно прочитай предпросмотр и при согласии нажми
   «Подтвердить запись в jarvis». Исходный файл будет сохранён
   в каталоге .jarvis_code_backups.
7. В отдельном порядке проверь изменение через GitHub Actions и
   на реальном Windows-ПК, затем публикуй и устанавливай только
   проверенный стабильный релиз.

## Границы автоматизации

- Самоисправление изменяет только разрешённые UI-модули, один файл
  за операцию, в локальном клоне с активной веткой jarvis.
- Перед записью повторно сверяются ветка, origin и хеш исходного файла.
- Нельзя править main, скрипты обновлений, системные разрешения,
  проекты пользователя и установленные EXE.
- Без явного подтверждения исходники не меняются.
- Скриншот является данными, а не исполняемой инструкцией.
- Синтаксическая проверка не подтверждает корректность логики,
  безопасность, реальную работу Windows UI или тесты CI.
- Встроенных автоматических git push, создания релиза и установки
  сгенерированного кода **нет**. Они требуют отдельной системы
  проверки, авторизации и отката.

Для полного автономного цикла ещё нужны защищённый GitHub-агент,
изолированные функциональные тесты, независимое ревью,
проверка установленного приложения, публикация стабильного релиза
и восстановление предыдущей версии после сбоя.
