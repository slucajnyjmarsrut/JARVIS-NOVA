# NOVA SELF-DEVELOPMENT 2.0 — безопасное самоисправление JARVIS

Новая функция позволяет описать проблему текстом или приложить скриншот с
красными отметками и подготовить **предложение** исправления интерфейса.

**Важно:** это ещё не полноценный автономный разработчик и не механизм
самопубликации. Изменения исходников выполняются только после подтверждения.
Сгенерированный код не запускается во время проверки предложения.

## Использование

1. Через меню ⚙ проверь локальную Qwen или отдельно разреши FreeLLM.
   Для FreeLLM появится предупреждение о передаче исходного файла внешнему ИИ.
2. Отправь скриншот кнопкой «СКРИН», обведи проблемные места и отправь его
   локальной Qwen на анализ. Можно обойтись и без скриншота.
3. Напиши «Джарвис, исправь себя» либо выбери «Самоисправление · только jarvis»
   в меню ⚙. Откроется отдельное окно.
4. Выбери **клон исходников** JARVIS-NOVA из GitHub на ветке `jarvis`,
   а не папку установленного EXE. Нужен официальный origin
   `slucajnyjmarsrut/JARVIS-NOVA`.
5. JARVIS предложит один разрешённый файл интерфейса по тексту ошибки.
   Выбор можно изменить вручную.
6. Нажми «Подготовить исправление». JARVIS проверит Python AST, сравнит
   потенциально опасные вызовы с оригиналом и покажет **полный diff**:
   строки со знаком `-` удаляются, строки с `+` добавляются.
   Ниже виден полный предлагаемый новый файл.
7. Прочитай изменения. Если согласен, нажми «Подтвердить запись в jarvis».
   Перед записью повторно сверяются ветка, origin, исходный SHA256,
   предложенный SHA256 и опасные операции.
8. Если результат не устраивает, в том же окне можно нажать
   **«Отменить последнее исправление»**. JARVIS восстановит исходный файл
   **только если он не менялся после подтверждённого исправления**.
   При этом новая версия также сохраняется в резервной копии.
9. После локального изменения отдельно проверь код в GitHub Actions и
   на настоящем Windows-ПК. Публикация стабильного Release и обновление
   установленного приложения пока выполняются отдельно.

## Защита

- Только исходный клон с официальным origin и Git-веткой `jarvis`.
  Ветка `main` не изменяется.
- Один файл за операцию, только из разрешённого списка UI-модулей.
  Установленные EXE, скрипты обновления, настройки, проекты, секреты
  и пользовательские данные не являются целями самоисправления.
- Проверка риска блокирует **новые/изменённые обнаруженные** вызовы
  запуска команд, редактирования файлов, сети, рефлексии и ряд
  чувствительных импортов. Эта проверка консервативная и неполная:
  она **не гарантирует безопасность** любого Python-кода.
- Ни одна строка из скриншота не считается инструкцией, разрешающей
  выполнение кода или выдачу полномочий.
- Синтаксический анализ не запускает предложенный Python-файл.
  Проверка AST не доказывает правильность работы программы.
- Отмена доступна в текущем окне после подтверждённого изменения.
  Оригиналы и отменённые версии находятся в
  `.jarvis_code_backups/`, эта папка исключена из Git через `.gitignore`.
- Автоматических `git push`, коммитов, публикации релизов или
  установки новых EXE у этой функции **нет**.

## Тестирование

Отдельный GitHub Actions workflow
`.github/workflows/self-development-gate.yml` работает **только на
ветке `jarvis`** в Windows Server 2022/2025 и Ubuntu. Он проверяет:

- распознавание команды самоисправления;
- запрет других Git-веток и постороннего origin;
- блокировку опасных добавлений в предлагаемом коде;
- целостность предпросмотра по SHA256 и запрет скрытой подмены;
- правильность полного diff;
- подтверждение записи и сохранение исходной версии;
- восстановление после исправления и отказ при сторонних правках;
- обработку локальных скриншотов и существующий контракт обновления.

Workflow получает только доступ на чтение репозитория, не публикует
релизы и не отправляет код в `main`. Проверки Windows GUI, реальной
Qwen, FilmCraft, Roblox и готового установщика остаются отдельными.

## Что ещё необходимо для полного самообновления

Авторизованный сервис для отправки одобренного кода в `jarvis`,
изолированные функциональные испытания реальных сценариев, независимый
аудит, воспроизводимая Windows-сборка, проверка издателя и релиза,
сохранение пользовательских настроек, откат установленной программы
после ошибки и отдельное подтверждение установки.
