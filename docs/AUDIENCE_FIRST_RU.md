# JARVIS NOVA: сначала аудитория → затем сценарий → съёмка → монтаж → оценка

**Статус:** функциональность реализована в исходниках DEV-ветки. Windows GUI/инсталлятор после этих изменений должны быть отдельно собраны и проверены. Старая DEV-сборка не содержит анализа канала.

## Как JARVIS узнаёт, что нравится зрителям

1. Владелец своего канала открывает YouTube Studio → Аналитика → **Расширенный режим** → **Экспортировать текущий вид** → CSV (выберите видео и нужный период).
2. В JARVIS открывает «Видео / Вирусные ролики» → «1. Анализ аудитории канала (CSV)» → выбирает **свой** CSV и подтверждает доступ к данным. Для другого сервиса подходит CSV с колонками названия ролика и просмотров; другие поля опциональны.
3. Модуль **«Аналитик аудитории»** сопоставляет просмотры и (при наличии) лайки, комментарии, досмотры и другие метрики, выявляет *повторяющиеся слова* из названий успешных роликов. **Не притворяется, что видит подписчиков, демографию, скрытые графики или комментарии**, если этих данных нет в экспорте.
4. **«Редактор тем»** рекомендует тему, **«Редактор зацепки»** усиливает первые три секунды, **«Специалист по удержанию»** проверяет структуру сцен, **«Редактор публикации»** предлагает честный заголовок и завершающий призыв.
5. Только после анализа JARVIS составляет сценарий локальной моделью Qwen, зачитывает инструкции съёмки через TTS и собирает MP4 локальным FFmpeg.
6. **После монтажа** «Эксперт итоговой оценки» проверяет реальный MP4 (длительность, наличие аудио), структуру сценария, темп, тему и статистику канала, сохраняет `FINAL_AUDIENCE_REVIEW_RU.md` и `FINAL_AUDIENCE_REVIEW.json`. Кнопка «4. Оценить для аудитории» позволяет повторить оценку.

## Обязательные ограничения

- Индекс 0–100 — **эвристическая оценка соответствия данным канала**, **НЕ** процент вероятности вирусности и не прогноз числа просмотров. Необученные модели не способны надёжно вычислить вероятность «залёта» только по видео.
- Только если есть **не менее трёх** прошлых видео с совпадающей темой, можно показать диапазон **исторических** просмотров для ориентировки. Это **не обещание будущих результатов**.
- Канал может иметь мало видео, смешивать Shorts с длинными выпусками, периоды могут различаться; метод не устраняет эту неоднородность. Для уверенной оценки нужны данные о показах, удержании, первых секундах и последующих результатах опубликованных роликов.
- Без CSV аналитика канала не подменяется поисковыми трендами. Google Trends (по отдельному согласию) — это поисковый спрос, не предпочтения вашей аудитории.
- CSV читается **локально** из выбранного файла. Пароли, токены, браузерные cookie не запрашиваются. В локальную Qwen передаются только агрегаты, **не оригинальный CSV**. Публикации в соцсети не выполняются.
- Подключение YouTube Analytics API с OAuth `yt-analytics.readonly` — будущая отдельная интеграция. Сейчас кнопка запрашивает **только экспорт CSV**; не нужно передавать свой пароль.

## Поддерживаемые столбцы CSV

Обязательно: `Video title` (или `Content`, `Title`, `Название видео`) и `Views` (`Просмотры`).

Опционально: `Likes`, `Comments`, `Shares`, `Average percentage viewed`, `Average view duration`, `Video duration`, `Impressions click-through rate`, `Impressions`, `Date`. Поддерживаются русские синонимы, запятая или точка в процентах и CSV-разделители `,`, `;`, `tab`.
