# Автообновления JARVIS NOVA — Windows

После запуска JARVIS NOVA проверяет официальные стабильные GitHub Releases
в фоновом потоке. Дальше проверка повторяется раз в 12 часов, пока приложение
работает. Переписка и видеомонтаж не блокируются сетевой проверкой.

## Использование

1. Установи JARVIS NOVA из полноценного Windows-установщика. Версия,
   запущенная напрямую из Python, не скачивает и не устанавливает обновления.
2. Нажми кнопку ⟳ рядом с ⚙ или выбери «Автообновления» в меню команд.
3. По умолчанию включены автоматические проверка/загрузка и применение
   обновления после 10 минут без нажатий клавиатуры/мыши.
4. Когда обновление скачано и проверено, нажми
   «Обновить и перезапустить», чтобы не ждать простоя.
5. «Отложить до следующего запуска» отменяет автоматический перезапуск
   в текущей сессии. В настройках можно полностью отключить автообновление.

Обновление не перезапускает приложение, если пользователь пишет сообщение,
создаёт ролик или выполняет задачу. После закрытия программы отдельный
локальный процесс запускает проверенный установщик и возвращает JARVIS
на экран. Настройки и пользовательские проекты хранятся отдельно от
каталога установки и остаются после обновления.

## Защита

- Только официальные стабильные версии из GitHub Releases данного репозитория,
  а не сборки Actions, ветки Git или произвольные ссылки.
- Проверяется HTTPS-хост, точное имя, GitHub SHA256, полный размер,
  отдельно SHA256 каждой части больших установщиков, структура EXE.
- Кэш помещается в %LOCALAPPDATA%/JarvisNova/Updates.
- Не запускаются удалённые скрипты или команды оболочки.
- При ошибке установки прежняя версия перезапускается, если она сохранилась.
- Для максимальной безопасности издателю следует подписывать установщик
  Windows Authenticode: один только SHA256 не подтверждает личность издателя.

## Как выпускать обновления

Владелец проекта сначала должен получить успешную Windows-сборку,
испытать её на чистом Windows, согласовать новую версию во всех маркерах
(auto_update.APP_VERSION, installer/JarvisNova.iss,
assets/APP_RELEASE_VERSION.txt), а затем опубликовать GitHub Release
с тегом vX.Y.Z и asset:

JARVIS-NOVA-X.Y.Z-OFFLINE-SETUP.exe

GitHub Release asset должен содержать digest sha256, размер и state uploaded.
Если файл больше лимита GitHub на один asset, используй
scripts/split_release_installer.py и добавь в описание релиза строки:

JARVIS-NOVA-INSTALLER-SHA256: <64 lowercase hex characters>
JARVIS-NOVA-INSTALLER-SIZE: <installer bytes>

До появления следующего официального стабильного релиза приложение
корректно покажет «Новых стабильных обновлений пока нет».
На дату реализации публичных стабильных GitHub Releases в репозитории
не было. Автообновления не работают для исходников или непроверенных
dev-артефактов; публикация релизов остаётся отдельным шагом владельца.

## Lite и Offline

JARVIS проверяет и скачивает только обновление своей редакции.
Lite не заменится тяжёлой Offline-версией без решения пользователя.
Для официального Lite релиза нужно точное имя
JARVIS-NOVA-X.Y.Z-LITE-SETUP.exe; для полного —
JARVIS-NOVA-X.Y.Z-OFFLINE-SETUP.exe.
