# Автоматические обновления JARVIS NOVA (Windows)

## Работа пользователя

В **установленной** версии с поддержкой автообновлений JARVIS сам проверяет официальные стабильные GitHub Releases этого репозитория после запуска и далее примерно раз в 12 часов. Нет необходимости открывать сайт, скачивать и удалять старую программу. По обнаружении релиза с новой версией JARVIS скачивает полный установщик в `%LOCALAPPDATA%\\JarvisNova\\Updates`, проверяет точный размер и SHA-256, ожидает завершения активных операций, передаёт обновление отдельному *локальному* исполняемому файлу и закрывается. Помощник дожидается завершения основного процесса, ещё раз проверяет GitHub Release и SHA-256, запускает Inno Setup в тихом режиме, проверяет версию в установленном приложении и запускает JARVIS снова. Настройки и обученные названия программ в `%LOCALAPPDATA%\\JarvisNova` не удаляются.

**Если интернета нет или нет нового релиза**, JARVIS продолжает работу. Если проверка или скачивание не прошли, никакая установка не запускается. Если установщик сообщил об ошибке, помощник пытается снова запустить предыдущее приложение (если его файлы остались в целости). Полный откат после повреждения установленной программы **пока не гарантирован**.

Автообновления не выполняются при запуске из Python-исходников, только в установленной Windows-сборке с `JarvisNovaUpdater.exe`. Ранее установленные версии JARVIS без этого механизма не могут сами получить его задним числом: требуется единожды установить версию, уже содержащую обновлятор.

## Безопасность и публикация нового релиза

В GitHub пока нет опубликованных Releases. Поэтому эта функция **не будет устанавливать что-либо**, пока разработчик отдельно не одобрит официальный стабильный релиз. Коммиты веток, артефакты Actions, prerelease и draft игнорируются. Никакой Release данным изменением автоматически не публикуется.

Будущие релизы для автообновления обязаны выполнять следующие условия одновременно:

1. Релиз опубликован (не draft/prerelease) **только** в `slucajnyjmarsrut/JARVIS-NOVA`, с тегом строго `vMAJOR.MINOR.PATCH` (например, `v0.5.19`).
2. Релиз содержит **ровно один** готовый Inno Setup EXE по имени `JARVIS-NOVA-0.5.19-OFFLINE-SETUP.exe`, с GitHub API `digest: sha256:<64 hex>`, корректным размером и состоянием `uploaded`.
3. В коде увеличены `auto_update.APP_VERSION`, `assets/APP_RELEASE_VERSION.txt`, а в `installer/JarvisNova.iss` — `AppVersion`, `VersionInfoVersion` и `OutputBaseFilename`. Каждый релиз должен пройти тройные Windows-тесты установщика, реальный FFmpeg и офлайн-модели. Нельзя переименовывать тестовые DEV-сборки в официальный релиз без проверок и отдельного решения пользователя.
4. Необходимо сохранять тот же `AppId` Inno Setup и каталог пользовательских настроек, чтобы обновление было поверх текущей установки.
5. Контрольная сумма из GitHub API защищает от подмены на пути передачи, но **не заменяет отдельную цифровую подпись Authenticode издателя**. Для широкого выпуска рекомендуется подписать EXE сертификатом и дополнительно проверить цифровую подпись в установщике.

Все данные о доступных обновлениях передаются по HTTPS через GitHub API. Установщик скачивается только с `github.com` с переходами на ограниченный набор хостов GitHub Release CDN. Передача видеороликов, голосовых записей, скриншотов или моделей для обновления не производится. Новые файлы из Release исполняются только после проверки SHA-256, метаданных и ожидания завершения приложения.

## Технические ограничения испытаний

`tests/test_auto_update.py` проверяет сценарии недоверенных адресов, неверного хеша, битого релиза, повторных попыток, отдельного процесса и восстановления после отказа на синтетических локальных данных. `scripts/test_installer.ps1` проверяет наличие и запуск обновлятора внутри настоящей установки. В условиях CI без опубликованного официального обновления невозможно подтвердить реальный переход **между двумя версиями** и наличие доверенной Authenticode-подписи. Эти проверки нужно отдельно провести на чистой Windows до публичного выпуска.
