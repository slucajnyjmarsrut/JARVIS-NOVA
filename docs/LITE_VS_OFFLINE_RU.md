# JARVIS NOVA Lite и Offline — размер установщика

Две редакции одной программы, обе только текстовые, с программированием,
Roblox, FFmpeg, FilmCraft и инструментами для видео.

- **Lite**: без встроенных 1,9 ГБ весов Qwen Vision. Быстрые сценарии
  работают сразу; локальный разговорный ИИ и распознавание картинок
  становятся доступны после отдельной загрузки Qwen.
- **Offline**: содержит Qwen3-VL 2B в установщике, работает полностью
  локально сразу после установки.

## Загрузка Qwen в JARVIS Lite

В главном окне нажми видимую кнопку **«СКАЧАТЬ QWEN»** или введи
`скачай qwen`, затем подтверди загрузку примерно 1,9 ГБ с
официального реестра Ollama. Команда скачивания **не запускает
повторный поиск по дискам**. Поиск ранее скачанных моделей — отдельная
кнопка «НАЙТИ МОДЕЛИ» и требует отдельного подтверждения.
Кнопка **«⚙ НАСТРОЙКИ»** доступна в заголовке окна.
Нужно минимум 3 ГБ свободного места и интернет. Загрузка не стартует
автоматически при запуске JARVIS. При скачивании прогресс отображается
в строке состояния. После загрузки все блобы сверяются с SHA256
их локального официального манифеста.

Веса хранятся в папке пользователя:
%LOCALAPPDATA%/JarvisNova/Models/ollama

После обновления JARVIS весы повторно скачивать не нужно.
Если на диске уже найдена `qwen2.5-coder:7b`, это отдельная кодовая
модель. Она не заменяет Qwen3-VL для чата и изображений. Её можно
выбрать в окне «Программирование» после согласия проверить уже
запущенный локальный Ollama на `127.0.0.1:11434`. Нахождение файлов
не означает, что Ollama может модель запустить.
Но если установить Qwen в Lite, общий размер файлов на диске увеличится
примерно на 1,9 ГБ. **Экономия главным образом в первоначальной загрузке
и обновлении приложения**. Точные размеры можно узнать из отчёта
LITE_SIZE_REPORT.json в успешном запуске GitHub Actions.

## Установщики и безопасность

- windows-lite.yml собирает компактный Lite + отчёт размера.
- windows-offline.yml собирает полный офлайн-установщик с Qwen.
- Оба варианта сохраняют пользовательские проекты в LocalAppData.
- Если перейти с полной установки на Lite, установщик удаляет только
  прежнюю копию модели ВНУТРИ ПАПКИ ПРОГРАММЫ. Отдельный пользовательский
  кэш Qwen и проекты не затрагиваются.
- Модель загружается только с разрешения; переносимый Ollama запускается
  на 127.0.0.1. Никаких голосовых моделей в Lite нет.
- Сначала требуются успешная Windows-сборка, тест установленного EXE и
  проверка на чистой машине. DEV-артефакты не считаются стабильными релизами.

Для автоматического обновления издатель должен опубликовать стабильный
GitHub Release с точным именем установщика и SHA256; случайные сборки
из GitHub Actions не устанавливаются автоматически.


## Понимание команд через локальную Qwen

Когда Qwen3-VL подключена, JARVIS сначала проверяет известные точные
команды, а для других явных просьб может отдельно попросить локальную
Qwen классифицировать намерение (например «можешь открыть монтажный
редактор» или «хочу перейти к параметрам»).

Модель может вернуть только название одного заранее разрешённого действия.
Она не может передавать JARVIS shell-команды, произвольные пути, файлы
или действия над ПК. Предложения низкой уверенности и обычные вопросы
остаются перепиской. Распознавание выполняется отдельным потоком, только
через локальный адрес Ollama; при сбое остаётся обычный чат.

Доступ к экрану и управление ПК всегда требуют отдельного подтверждения
в окне JARVIS. Классификация не запускает захват изображения, установку
модели, публикацию или изменение файлов без существующих разрешений.
Если Qwen ещё не подключена, старый детерминированный режим команд
остаётся доступен.

## Начните без инструкций (Lite)

При первом запуске в самом верху есть **четыре понятных действия**:
**«СОЗДАТЬ ВИДЕО»**, **«СМОНТИРОВАТЬ»**,
**«НАПИСАТЬ КОД»**, **«РАЗОБРАТЬ СНИМОК»**.
Нажатие открывает соответствующий редактор и само по себе
не запускает экспорт, не выдаёт доступ к экрану и не меняет файлы.
Под ними видны отдельные кнопки **«НАЙТИ МОДЕЛИ»**,
**«СКАЧАТЬ QWEN»** и **«РАЗРЕШИТЬ ЭКРАН»** (с подтверждениями).

Можно **не нажимать кнопки вообще**: внизу напиши обычную просьбу,
например «хочу сделать видео» или «смонтировать видео», и нажми Enter.
Короткие неясные слова («видео», «модель», «экран», «код») вызывают
вопрос с вариантами, а не запускают случайную функцию.
Кнопка настроек всегда видна. Поле ввода должно оставаться
доступным даже в компактном окне 390 × 600.

Для чата и распознавания свободных команд требуется локальная Qwen3-VL.
Если её нет, на экране показывается прямое объяснение и кнопка
загрузки; заранее встроенные действия и редакторы остаются доступны.
Если модель уже есть — интерфейс сообщает, что Qwen подключена.
Нельзя считать наличие Qwen Coder доказательством поддержки изображений.

Это тестовая версия: Windows CI проверяет элементы, клики и
инсталлятор, но удобство для всех людей невозможно доказать без
наблюдения за обычными пользователями на их компьютерах.

## Поэтапная работа над кодом

В разделе **НАПИСАТЬ КОД** режим полного проекта сначала показывает план:
архитектура → реализация → тесты и документация → общая проверка.

Каждый этап создаётся отдельно и проверяется **до** следующего.
Для Python это реальный разбор синтаксиса всех файлов промежуточного
проекта (AST); для остальных языков проверяются доступные форматы,
а общая компиляция или структурная проверка выполняется отдельно.
Ошибочный этап исправляется отдельно (не более трёх попыток);
после третьего отказа работа останавливается и исходники пользователя
остаются без изменений.

После трёх этапов весь проект проверяется **совместно**, и результат
виден в окне программирования. «Синтаксис корректен» **не** означает
«функциональные тесты пройдены». Независимые Python-тесты в Docker
исполняются только после отдельного согласия. Сгенерированный проект
не записывается в пользовательскую папку без существующего подтверждения.

Таким образом, виден реальный прогресс «план → шаг → проверка →
следующий шаг → общая проверка», а не только текстовое обещание ИИ.

## JARVIS работает по шагам

**Написать код.** При выборе полного проекта JARVIS сначала показывает
план из четырёх этапов. Затем создаёт архитектуру, реализацию, тесты и
документацию, проверяя промежуточные результаты в отдельных временных
папках. При ошибке JARVIS повторяет **только непрошедший этап**, после
чего проверяет **все файлы проекта вместе**. Выполнение сгенерированного
кода в Windows запрещено; синтаксическая проверка не гарантирует
корректной работы программы. Функциональные Python-тесты в Docker
запускаются лишь после отдельного разрешения. Запись в настоящий проект
остаётся под контролем пользователя.

**Создать видео.** Видеостудия отображает ход генерации сценария:
план сюжета → отдельные кадры и подписи → формальная проверка всей
раскадровки. Если Qwen выдаёт повторные или неверные сцены, JARVIS
возвращает замечания и повторяет неудачный вариант в пределах
установленного лимита. Если настоящий сценарий Qwen так и не прошёл
проверку, запасной вариант **всегда обозначается как шаблон без ИИ**.
Факты, смысл сюжета и художественное качество требуют просмотра человеком.

**Полный автомонтаж** после отдельного подтверждения показывает этапы
подбора лицензированных исходников, загрузки, сборки и итоговой
технической проверки MP4. Загрузка медиа и любые изменения файлов
не выполняются тайно.
