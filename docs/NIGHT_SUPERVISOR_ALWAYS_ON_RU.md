
# JARVIS NOVA Supervisor — постоянная фоновая работа

**Supervisor включён по умолчанию.** Он работает независимо от окна JARVIS и
проверяет очередь каждые 15 секунд. Не нужно нажимать кнопку «Запустить очередь»:
как только ты добавил конкретную задачу и разрешил запись новых файлов,
Supervisor самостоятельно запускает её, проверяет результат и сохраняет его.

В установленной Windows-версии JARVIS запускает отдельный процесс
`JarvisNova.exe --supervisor-daemon`, который остаётся активен после закрытия
графического окна. Одновременно работает максимум один диспетчер очереди;
лишние экземпляры не выполняют ту же задачу повторно благодаря Windows-мьютексу
и межпроцессной блокировке очереди.

**При установке:** видимая (выбранная по умолчанию) опция «Запускать фоновый
JARVIS Supervisor при входе в Windows» создаёт только обычный ярлык текущего
пользователя в папке автозагрузки Windows, без прав администратора.
Отключить автозапуск можно при установке или в Windows → Автозагрузка
(или удалив ярлык `JARVIS NOVA Supervisor` в папке пользователя).
Закрытое окно JARVIS не завершает уже запущенный фоновый процесс.
После полного выключения ПК работа возобновится **только после входа в Windows**,
а не до загрузки системы; отключение питания всегда прерывает вычисления.

В окне Supervisor кнопка **«Пауза Supervisor»** сохраняет `enabled=0` в
SQLite: фоновые задачи больше не запускаются, прерванный этап
приостанавливается после контрольной точки, и пауза действует после
следующих перезапусков. **«Включить Supervisor»** снова разрешает обработку
ранее одобренных заданий. Закрытие только окна настроек Supervisor НЕ ставит
его на паузу.

Supervisor может выполнить исключительно заранее заданные и отдельно
разрешённые локальные задачи четырёх фиксированных типов: сценарий,
Python-проект с проверкой синтаксиса, советы по монтажу, или анимированный
MP4 по теме. Самостоятельное создание новых целей, удаление или перезапись
пользовательских файлов, запись экрана, выполнение сгенерированного кода,
скачивание моделей, публикации и произвольные команды ОС запрещены.

Контроль памяти: при низком объёме свободной ОЗУ задача ожидает
восстановления; JARVIS может выгрузить только известные локальные
специализированные модели. Не больше двух повторных попыток после ошибок
памяти; контрольные точки и журнал SQLite сохраняются.
Готовность реальных моделей на конкретном ПК надо проверить отдельно.

Исходный (не собранный EXE) запуск использует фоновый поток и не продолжает
работать после закрытия Python-процесса. Автозапуск вместе с Windows действует
для пользовательской установленной версии с ярлыком, а не для исходников.
