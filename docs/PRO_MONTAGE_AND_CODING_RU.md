# JARVIS NOVA — монтаж и программирование: этап профессионализации

**Ветка: \`jarvis\`.** Это журнал реализованных возможностей, не маркетинговое
утверждение, что JARVIS уже равен Premiere Pro, DaVinci Resolve, VS Code,
Cursor или автономному senior-инженеру.

## Монтаж: анимация дополнительных дорожек

Открой **Многодорожечный монтаж** из меню JARVIS или видеостудии.
На каждое из трёх наложений (видео, PNG, логотип) доступны:

- Положение: 5 фиксированных позиций на экране.
- Масштаб по ширине, прозрачность, время появления и длительность.
- Анимация: \`static\`, \`fade-in\`, \`slide-left\`, \`slide-right\`,
  \`rise\`, \`drop\`.
- Время движения 0,15–1,2 секунды, но не длиннее самого слоя.

При экспорте FFmpeg вычисляет положение *для каждого кадра*.
Переходы — действительные фильтры, а не название в интерфейсе.
Сохранённый JSON-проект хранит тип движения и время. Старые проекты
без этих полей загружаются со статическим положением по умолчанию.

Оригинальные кадры/звук остаются нетронутыми. Конечный MP4 создаётся
только по разрешению пользователя, проверяется кодек/длительность/размер
и не перезаписывает ранее существующие видео. Тесты включают реальные
прогоны каждого типа анимации с FFmpeg.

**Следующие ограничения монтажа:** пока отсутствуют произвольные кривые
keyframe, GPU-предпросмотр *всего* готового монтажа в реальном времени,
видеомаски, трекинг объектов и профессиональный цветовой grading.
Это нужно разрабатывать и проверять отдельно. Не заявлять уровень
Premiere/After Effects как уже достигнутый.

## Программирование: инженерная рецензия

Открой **Программирование → Универсальный ИИ-разработчик**.
После генерации JARVIS покажет AST-рецензию Python-модулей:

- Потенциально опасные системные операции, \`eval\`, \`exec\`,
  \`os.system\`, \`subprocess(..., shell=True)\`, небезопасную десериализацию.
- Голые \`except\`, исключения, которые молча игнорируются.
- Наличие тестовых файлов и инструкции README.
- Перед подтверждением файлов с обнаруженными рисками просит
  *дополнительное* разрешение.

Это **эвристическая рецензия**, не гарантия безопасности и не аудит
всего стороннего кода. Проект проверяется статически до записи.

## Изолированный запуск Python-тестов

Новая кнопка **«Тесты Python в Docker (с подтверждением)»** проверяет
сгенерированный Python-проект *до установки* при следующих условиях:

1. Пользователь сам устанавливает Docker Desktop и убеждается, что он
   безопасно настроен на его Windows-ПК.
2. Пользователь **вручную** загружает доверенный образ
   \`python:3.12-slim\`, если его нет локально. JARVIS никогда
   не делает \`docker pull\` сам.
3. После отдельного согласия JARVIS копирует лишь ограниченный набор
   \`*.py\` файлов в новый временный каталог. Скрытые файлы,
   \`.env\`, токены, папки Git, зависимости и исходная папка проекта
   **не монтируются** в контейнер.
4. Docker запускается с \`--network none\`, \`--read-only\`,
   \`--cap-drop ALL\`, \`--security-opt no-new-privileges\`,
   ограничениями RAM/CPU/процессов/времени и без shell.
5. Отчёт явно сообщает число реально найденных тестов и
   \`passed\` / \`failed\` / \`skipped\`. **0 тестов — не успех.**
6. Если Docker отсутствует, образ недоступен или нет тестов,
   JARVIS показывает «не проверено», не запуская сгенерированный
   Python-код прямо на Windows.

Важные границы: в первой версии тестируется только **новый**
сгенерированный Python-план. Правки в старом проекте потребуют
полного контролируемого снимка. Код внутри контейнера всё равно может
быть вредоносным; Docker снижает риски, но **не равен полной изоляции
от уязвимостей ядра/демона**. Для явно недоверенных программ
используйте отдельную одноразовую виртуальную машину.

Другие языки (Java, Luau, C++, TypeScript и т. д.) по-прежнему
проходят только имеющиеся статические/синтаксические проверки.
Компиляция не считается доказательством работоспособности.

## Регрессионные тесты

- \`python -m unittest discover -s tests -p test_code_quality_review.py -v\`
- \`python -m unittest discover -s tests -p test_code_test_sandbox.py -v\`
- \`python -m unittest discover -s tests -p test_multitrack_composer.py -v\`
- \`python scripts/run_text_only_tests.py\`

CI тестирует границы Docker с имитацией запуска, **не запускает
произвольные AI-проекты на GitHub Runner**. Реальная функция запуска
проверяется только на ПК с Docker после разрешения пользователя.

## Статус поставки

Изменения лежат только в ветке \`jarvis\`, не \`main\`. Успех CI для
конкретного коммита и подписанный стабильный релиз — разные вещи.
DEV EXE требует проверки на реальном Windows-ПК. JARVIS не устанавливает
неподписанный исполняемый файл автоматически.
