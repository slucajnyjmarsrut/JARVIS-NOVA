# JARVIS NOVA — единый пакет интеграции Java / Roblox Luau

**Основа:** ветка `jarvis` репозитория `slucajnyjmarsrut/JARVIS-NOVA`, проверенная по состоянию исходников `205109072883f98642d15c253e6bdac1849d869d` (0.5.18-dev).

Этот архив **не содержит всего репозитория, весов моделей, Windows EXE или установщика**. Он содержит новые исходники, тесты и один проверяемый интегратор, который применяет изменения к **полной локальной копии** JARVIS NOVA. GitHub не изменяется.

## Что реализовано

- Новый пункт в меню «Программирование» внутри основного Tk-интерфейса JARVIS NOVA.
- Голосовые и текстовые команды: «Джарвис, создай проект на Java», «Джарвис, напиши скрипт Roblox …». Обрабатываются в `Jarvis.handle_text`, не перехватывают простое «Открой Roblox Studio».
- Java: создание исходников, компиляция через `javac` без выполнения полученной программы или процессоров аннотаций, до трёх попыток исправления ошибок компиляции локальной моделью.
- Roblox: создание Luau-файлов и конфигурации Rojo `default.project.json`, текстовая проверка, дополнительная компиляция через `luau-compile`, если утилита установлена. **Настоящий Roblox Studio Play Test не выполняется автоматически**.
- Локальная генерация: если запущено главное приложение, используется его упакованный runtime Ollama/Qwen; в автономном окне — локальная Ollama `127.0.0.1:11434`. Ни одна строка исходника не отправляется в облако.
- Создание и изменение уже существующих файлов по плану, явное подтверждение пользователя, хеш-проверка исходного состояния, резервные копии в `.jarvis_code_backups`. Без подтверждения файлы не изменяются.
- Кнопки «Открыть папку проекта» и «Открыть IDE». Для Java ищется установленная Visual Studio Code; для Luau — Roblox Studio. Самопроизвольная публикация игр и выполнение сгенерированных программ отключены.
- Монтаж не заменён: уже имеющиеся `viral_studio.py` и `smart_montage.py` в оригинальном репозитории сохраняются. В пакет включена независимая FFmpeg-проверка, которая может вызвать настоящий `render_video()` в полном репозитории.
- Новые Python-тесты попадают в `tests/` и автоматически подхватываются существующим `unittest discover` в CI.

## Интеграция в копию исходников

Откройте терминал в **распакованной папке этого патча** с установленным Python 3.11+.

```powershell
python integrate_into_jarvis.py "C:\path\to\JARVIS-NOVA" --dry-run
python integrate_into_jarvis.py "C:\path\to\JARVIS-NOVA"
```

Первый вызов только проверяет совместимость. Второй переносит исходники в папку репозитория, обновляет `main.py` и `jarvis_nova.spec`, делает резервные копии оригиналов в `.jarvis_code_backup` и запускает тесты новых модулей. Повторная интеграция ничего не меняет.

Из папки JARVIS NOVA можно дополнительно запустить:

```powershell
python -m unittest discover -s tests -v
python scripts/verify_video_integration.py --repo .
```

Для Python-проверок достаточно стандартной библиотеки. Для генерации нужен локальный Ollama/Qwen; для реальной Java-компиляции — JDK; для проверки видео — FFmpeg, ffprobe и Pillow. Для Roblox Studio нужен отдельно установленный Roblox Studio, а для синхронизации проектов — Rojo (по желанию).

## Windows-сборка

В оригинальном репозитории имеется `.github/workflows/windows-offline.yml` и `jarvis_nova.spec`. Для **достоверной** проверки EXE и установщика необходимо собрать его на Windows runner с полной папкой `assets/models` и запустить настоящий E2E/installer smoke test. На Linux-контейнере готовый Windows установщик собрать и проверить нельзя. Успех Python-тестов **не является доказательством**, что Windows EXE или интерактивный Roblox Studio работают.
