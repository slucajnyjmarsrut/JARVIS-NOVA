# JARVIS NOVA — безопасная разработка Python с тестами и исправлениями

**Ветка проекта: только \`jarvis\`; \`main\` не изменять.**

## Возможности разработчика

JARVIS уже умеет создавать многофайловые проекты для разных языков,
показывать исходники и unified diff, выполнять статические проверки
и предлагать правки до ручного согласия.

Для **новых Python-проектов** в окне «Универсальный ИИ-разработчик»
добавлены действия:

- **«Тесты Python в Docker»**: скопировать только Python-файлы в
  одноразовую папку, после согласия запустить \`unittest\` внутри
  ограниченного Docker-контейнера;
- **«Исправить по тестам (до 2)»**: получить отчёт тестов и,
  если они упали, попросить ИИ предложить не более двух
  изменений с последующей повторной статической проверкой
  и отдельным тестом каждой версии;
- **«Подтвердить запись»**: только после просмотра кода/diff
  и явного согласия. Результаты Docker сами не устанавливаются
  и не публикуются.

## Изоляция и ограничения

- **Docker обязателен**: JARVIS не исполняет сгенерированный Python
  напрямую в Windows, даже если Docker отсутствует.
- Нужен заранее установленный, локально доступный образ
  \`python:3.12-slim\`. Автоматическое скачивание образа отключено.
- Docker запускается с \`--pull never\`, \`--network none\`,
  без привилегий, без Linux capabilities, с read-only файловой системой,
  ограничениями CPU, памяти, PID и времени.
- Исходный проект в контейнер не монтируется: используется копия
  выбранных файлов \`.py\`. \`.env\`, ключи и бинарные файлы не
  копируются. Это не повод хранить секреты прямо в Python-исходниках:
  **такие секреты всё ещё могут попасть в копию**.
- При истечении времени JARVIS пытается принудительно удалить
  только собственный уникально именованный контейнер. Если
  Docker-очистка не подтверждена, об этом сообщается.
- При отсутствии тестов, Docker или образа статус **SKIPPED**,
  не PASS. При нуле запущенных тестов успех не объявляется.
- После падения тестов запись неудачной версии блокируется.
- Если статическая AST-рецензия обнаруживает опасные операции,
  автоматические тесты/правки останавливаются до ручного разбора.

**Важно:** Docker снижает риски, но сам по себе не обеспечивает
математически гарантированную изоляцию от специально
созданного вредоносного кода. Не запускай заведомо вредоносные
проекты. Образы нужно получать из доверенного источника.
При работе через FreeLLM исходники и вывод тестов могут
отправляться внешнему провайдеру **только после отдельного согласия**.

## Не реализовано

- Универсальный запуск тестов для Java, C++, Rust, Roblox Luau
  и остальных языков в отдельной песочнице;
- автоматическое развёртывание/публикация программ;
- гарантия правильности или отсутствия уязвимостей по нескольким
  пройденным тестам;
- автономная запись в основную ветку GitHub — это запрещено.

## Проверки проекта JARVIS

\`python -m unittest discover -s tests -p test_code_test_sandbox.py -v\`

\`python -m unittest discover -s tests -p test_code_test_repair.py -v\`

\`python -m unittest discover -s tests -p test_code_gui_review.py -v\`

CI проверяет ограничения и логику тестов с имитацией Docker-команд,
а не реальное выполнение сгенерированного кода через Docker
на компьютере владельца. Это требует самостоятельного испытания
в установленной среде.
