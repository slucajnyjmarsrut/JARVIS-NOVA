# JARVIS NOVA — путь к качеству голоса уровня «Алисы»

**Ветка кода:** `jarvis`. **Цель:** приближаться к точности,
естественности и скорости хорошего русскоязычного ассистента. «Как у Алисы»
— ориентир, но не доказанный результат: внешняя система использует другие
модели, оборудование и инфраструктуру. Сначала измеряем на одинаковом звуке.

## Этапы (выполнять последовательно)

1. **Эталон качества и задержек — реализован инструмент, ожидаются реальные WAV.**
   Локальный `scripts/benchmark_russian_asr.py` оценивает WER (доля ошибок
   слов), CER (символов), долю обнаруженных обращений «Джарвис», ложные
   активации и время CPU-распознавания. Он не требует интернета и не сохраняет
   отдельные распознанные фразы. Тесты метрик встроены в Windows CI.
2. **Микрофон, шум и речь — готова локальная диагностика, нужны измерения.** Сравнить тихую речь,
   фоновые вентиляторы, разговорный темп и USB/Bluetooth. Исправлять
   обнаруженные причины потери фразы, не просто увеличивая чувствительность.
3. **Точность русского языка — предстоит измерение.** Сравнить Whisper Base,
   Whisper Small и согласованность с Vosk на одинаковых WAV. Вручную проверить
   названия программ и короткие команды; улучшать пороги только если падает WER
   без роста случайных запусков.
4. **Время ответа — предстоит измерение.** Разделить время до конца речи,
   декодирования, ответа Qwen и озвучки Silero. Оптимизировать самый медленный
   участок на конкретном Windows CPU.
5. **Регрессии и выпуск.** Windows 2022 и Windows 2025, настоящие контрольные
   модели, установщик/удаление, сохранение данных, затем измерение на
   физическом микрофоне пользователя. Зелёный CI ≠ одинаковое качество с Алисой.
6. **Новый интерфейс — ОЖИДАЕТ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ.** Концепт нарисован в
   чате. НЕ менять GUI или визуальную компоновку до явного «да».

## Микрофон: локальная диагностика без сохранения аудио

В исходном проекте Windows можно выполнить:

```powershell
python -m scripts.check_microphone_quality --seconds 5
```

Пять секунд говори в микрофон. Вывод содержит только сводные значения:
среднюю громкость, пиковый уровень по блокам, процент перегрузки и число
пропущенных аудиопакетов. Он помогает обнаружить неправильный микрофон,
слишком слабый сигнал или проблемы с Bluetooth/драйвером. Это не оценка WER
и не гарантия работы активации. Данные не передаются в сеть и не сохраняются.

## Как измерять офлайн

Записать **только с согласия** несколько десятков коротких команд и
разговорных фраз в WAV PCM16 (моно или стерео), 16/44,1/48 кГц. Записи
остаются в локальной пользовательской папке. В этой папке создать CSV
`samples.csv` в UTF-8:

```csv
audio,reference
sample01.wav,"Джарвис, открой блокнот"
sample02.wav,"Слушай, Джарвис, как дела"
sample03.wav,"Сегодня хорошая погода"
```

Из корня исходного проекта запустить:

```powershell
python -m scripts.benchmark_russian_asr --manifest .\samples.csv --model-path .\assets\base.pt --output-json .\base-score.json
python -m scripts.benchmark_russian_asr --manifest .\samples.csv --model-path .\assets\small.pt --output-json .\small-score.json
```

Пути к модельным файлам зависят от комплектации; в установленном EXE
файлы могут находиться внутри защищённого пакета. Утилита предназначена
для проверки исходного проекта с локальными контрольными моделями.

Сравнивать **один и тот же набор аудиофайлов**, отобранный без подсказки
модели. Смотреть прежде всего `wer` (меньше — лучше), `wake_recall`
(больше — лучше), `false_wake_rate` и `latency_p95_s`. Метрики на
синтетическом голосе НЕ эквивалентны реальному голосу человека.

Отчёт содержит **только агрегаты**. Утилита ничего не загружает в интернет,
не скачивает модели и не создаёт хранилище аудиозаписей. Файлы WAV остаются
у пользователя и могут быть удалены после оценки.
